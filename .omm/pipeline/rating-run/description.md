The rate-paper function (workflows/src/rating/rate-paper.ts), a singleton per request id with 300 minutes: it checks the request, checks the target is a paper LabsTrail published, then reads the R-KA's state and does only what is left. Each part of the score (the PDF link with the title and abstract, the text, the field check, Gemini's answer) is kept across attempts once it came back, which wait 2, 5, 15, 30, then 60 minutes: the field check runs once a run, and the scorer is asked once per attempt until it answers (ADR 0018). Once the oracle answers, an alert-orphan step alerts on an R-KA the contract will never record (the request cancelled meanwhile, or gone), an alert-oracle-moved step on one an oracle move may leave unrecorded, and for a settled request a notify step sends one activity message, each from a step of its own (ADR 0038); a run that never read the paper looks it up for the message first (find-paper). A run that gives up on a cause that passes by itself, the request still pending (any reason but setup and rating-unreadable, and an oracle that stopped on a conflict or its setup), sends a ⏳ Rating delayed message first (notify-delayed): why, that the reconciler retries it, when it would be cancelled, and the paper as far as the run read it; then it fails as before, and alert-on-failure stays silent on it. Started by the webhook's intake, the reconciler, or locally the page.
