publish-paper.ts: runPublish and the publish-paper Inngest function, a singleton per CID with a 45-minute budget. It verifies the event, then reads the Target KA's state and does only what is left (ADR 0007): read the paper, check a new paper's field once per run (ADR 0037), store its triples, start the mint and poll it (ADR 0008), retrying with step.sleep (ADR 0009). A KA already stored or minted keeps its first submitter. Refusals (not a PDF, too large, unparseable, no title, unreadable, no text, outside the field) end the run; failures carry publish-failed:<reason> for the paper's page, setup among them when GROBID refuses our credential or Gemini the field check's request. A paper this run minted is announced once to the maintainer's Telegram chat from a notify step (ADR 0038). It logs outside-field and field-unchecked through Inngest's logger.
